We are continuing the YouTube Content Studio project.

The foundation is already implemented and working:

* Dashboard
* Ideas library
* AI Strategist
* Shorts Script Studio
* Projects
* PostgreSQL
* OpenAI provider through Replit Secrets
* Responsive UI
* Existing API endpoints

Now implement Phase 2: **YouTube Research & Trend Intelligence Agent**.

IMPORTANT:
This application is specifically a YouTube content creation system. Do not turn it into a generic AI assistant.

## Goal

Build a research system that helps the AI answer:

"What should we create next on YouTube?"

The system should research real YouTube data where available, analyze videos/channels/topics, identify content opportunities, and feed the results into the existing AI Strategist and Ideas system.

Do NOT invent YouTube statistics, views, subscribers, rankings, trends, or channel performance.

If real data is unavailable, clearly mark the data as unavailable rather than generating fake numbers.

## 1. Research Dashboard

Create a new "Research" section in the main navigation.

It should contain:

* Search/topic input
* Language selector
* Region selector
* Content type selector:

  * Shorts
  * Long-form
  * Both
* Time range:

  * Today
  * This week
  * This month
  * Custom
* Research button

Show research results in a clean dashboard.

Each result should support:

* Video title
* Channel
* Published date
* Duration
* URL
* Available view count
* Available like count
* Available comment count
* Thumbnail
* Data source
* Data timestamp

If a metric is unavailable, display "Unavailable" instead of estimating it.

## 2. YouTube Data Integration

Create a modular YouTube data provider.

Do NOT hard-code the application around one provider.

Create an interface similar to:

YouTubeResearchProvider

with methods for:

* searchVideos()
* getVideoDetails()
* getChannelDetails()
* getTrendingVideos()
* getRelatedVideos()

Use the official YouTube Data API when credentials are configured.

Store credentials only in Replit Secrets.

Never expose API keys to frontend code.

Create a clear setup state when the YouTube API is not configured.

For example:

"Connect YouTube Data API to enable real research."

Do not use fake fallback data.

## 3. Trend Intelligence

Create an AI-powered analysis layer using the existing OpenAI provider.

The AI should analyze collected real data and identify:

* Frequently appearing topics
* Rising topics
* Repeated formats
* Common hooks
* Video length patterns
* Titles and title structures
* Content gaps
* Possible audience interests
* Opportunities for original content

Important:

Do not call something "trending" simply because it was generated by the AI.

Trend claims must be based on actual collected data.

Clearly distinguish:

REAL DATA

from

AI ANALYSIS / ESTIMATION.

## 4. Competitor / Channel Research

Allow the user to enter a YouTube channel URL or channel ID.

Create a channel research view showing available real data:

* Channel name
* Subscriber count if available
* Total views if available
* Video count if available
* Recent videos
* Recent Shorts
* Average views where it can be calculated from real retrieved videos
* Frequently used topics
* Frequently used title patterns

Do not invent missing metrics.

Add an "Analyze Channel" action.

The AI should then explain:

* What this channel appears to do well
* Repeated content patterns
* Strong hooks
* Weaknesses or gaps
* Opportunities to create something original

Do not encourage copying another creator's content.

The objective is competitive research and originality.

## 5. Opportunity Finder

Add an "Opportunities" area.

Based on REAL collected YouTube data, identify potential content opportunities.

Each opportunity should include:

* Topic
* Evidence
* Why it may be interesting
* Competition level
* Suggested format
* Suggested hook
* Estimated potential score
* Confidence
* Source videos

Important:

"Potential score" is an AI estimate, not a real YouTube metric.

Clearly label it as an AI estimate.

The AI must explain why it gave the score.

## 6. Connect Research → Ideas

This is very important.

Allow the user to click:

"Create Idea"

from any research result or opportunity.

It should automatically populate the existing Ideas system with:

* Topic
* Suggested title
* Hook
* Description
* Target audience
* Format
* Estimated duration
* Research evidence
* Source videos
* AI opportunity score
* Originality considerations

The idea should then appear in the existing Ideas library.

Do not create a separate disconnected idea system.

## 7. Research History

Create a research history section.

Store:

* Search query
* Filters
* Date/time
* Number of results
* Research status

Allow previous research sessions to be opened again.

## 8. Database

Extend the existing PostgreSQL schema with appropriate tables/models for:

* ResearchSession
* ResearchVideo
* ResearchChannel
* ResearchAnalysis
* ContentOpportunity
* ResearchSource

Use proper relationships with existing Idea and Project models where appropriate.

Do not duplicate existing models unnecessarily.

Use migrations safely.

## 9. UI

Keep the existing visual design.

The Research page should feel like a professional creator intelligence dashboard.

Use:

* clean cards
* tables
* filters
* charts only when backed by real data
* loading states
* empty states
* error states

Do not overload the interface.

## 10. API architecture

Keep the backend modular.

Create routes/services for:

* research search
* video details
* channel research
* trend analysis
* opportunity generation
* create idea from research

Use proper validation and error handling.

## 11. AI Provider

Continue using the existing OpenAI provider abstraction.

Do not create a second unrelated OpenAI integration.

The AI should receive structured research data and return structured analysis.

Use JSON/schema validation where appropriate.

## 12. Important restrictions

Do NOT implement:

* fake YouTube statistics
* fake trending videos
* fake channels
* fake analytics
* fake API responses
* fake publishing
* automatic YouTube uploads yet

Do NOT implement video generation yet.

Do NOT implement Replicate yet.

We are building the research/strategy layer first.
